# One physical Stage A/B acceptance window

**Preparation only.** This source change authorizes no workload stop, Tailscale pause, physical disconnection, feature write, sign-out, child connection or teardown. Stage A needs an approved exact v5 plan hash; Stage B and exact-child teardown need further separate approvals. Use an already elevated, same-account physical-console PowerShell, a second local observer, and the exact published checkout. Keep this procedure, the probe binary, the private baseline and recovery contacts available without internet.

## Before interrupting anything

1. Confirm each owner has reviewed the fresh private workload inventory and the six-project shutdown matrix. Approve a consistent MongoDB backup or disposable-data decision, Redis effective persistence and pending writes, and OpenBao dev-mode reconstruction or tested backup for **each** project. Record running container IDs, Compose configuration paths, bind mounts, volumes, original restart behavior, running WSL distributions, and exact owner-approved stop/resume commands. A healthy state or restart policy `no` is not data-safety evidence. If any owner or recovery path is missing, stop here.
2. Confirm local access does not depend on Tailscale or another remote connection. Record its connected state, profile, unattended behavior, service state, interface index, addresses and routes privately. Check whether an organization policy requires a disconnect reason or prohibits disconnect. Do not log out of Tailscale, change its profile, disable its driver, or edit its service startup mode.
3. Verify the same Windows account can sign in offline at the physical console, and identify a local recovery administrator and a second observer. Do this before a feature write. Arrange an independent way to obtain **separate exact-hash Stage A approval and post-result Stage B approval while this PC stays offline**. If approval cannot be received and recorded offline, end after the read-only plan using the no-journal abort; do not reconnect a journaled test midway. Save all application work and arrange the approved outage. Run the offline suite and capture the original child feature, enumerated sessions, RDP deny policy, `TermService`, listeners, firewall fingerprint, Sunshine/VDD observations and display state in a restricted local location. Do not upload raw captures or the plan hash.

## Operator-controlled isolation and read-only plan

Use the [workload pause procedure](workload-quiescence-runbook.md) for the exact approved Compose projects and running WSL distributions. Stop reviewed containers without deleting volumes, quit Docker Desktop, and terminate only approved WSL distributions. Verify no container, guest, HNS endpoint, host forwarding or listener remains. A failed `docker ps` alone proves nothing.

While still connected, the operator may use `tailscale down` as the smallest documented disconnect operation; [Tailscale documents `tailscale up` without flags as its reconnect operation](https://tailscale.com/docs/reference/tailscale-cli). If policy denies the command or its original state cannot be preserved, stop. Then physically unplug Ethernet/USB networking, turn off Wi-Fi, Bluetooth PAN and cellular/tethered uplinks, and have the second observer confirm severance. A `tailscale down` result alone does **not** establish isolation: the read-only diagnostic must show no address **and** no route on the formerly addressed tunnel, no unexplained virtual path, no guest path, and no ordinary RDP exposure. The numbered Hyper-V adapter is attributed only by its unique management-OS port MAC, internal switch ID/name, virtual identity, precise description and matching `vEthernet (switch)` label. Do not whitelist another tunnel or edit firewall rules.

From the repository root, with links physically severed:

```powershell
pwsh -NoProfile -File .\scripts\network-boundary-diagnostic.ps1 -OperatorConfirmedPhysicalSeverance
.\tests\.artifacts\ChildStreamFeasibilityProbe.exe plan-boundary I-CONFIRM-PHYSICAL-ISOLATION
```

Require `External=Pass`, `GuestPath=Pass`, `RdpExposure=Pass`, `virtual-paths-attributed=Pass`, a complete fingerprint and a printed v5 plan hash. Capture the hash privately. If any predicate fails or is unknown, **do not begin**. There is no new journal or feature write; verify journal absence and compare feature/RDP baseline with the original, then restore only the operator-changed network and workloads under the approved no-journal abort procedure in [Stage A](external-boundary-stage-a.md#abort-before-begin-boundary). This read-only plan is the first full offline rehearsal, not Stage A authorization.

## Separately approved Stage A, then Stage B

After explicit approval of the exact published SHA, machine, operator, v5 plan hash, one feature cycle and fresh physical-console sign-out/logon, run the [Stage A commands](external-boundary-stage-a.md#approved-transaction-only). The first write is `begin-boundary`; `prepare-boundary` writes feature intent before the non-atomic Windows API. Keep the second observer and links offline through the fresh sign-in. `verify-boundary` must report `StageAValidated` with a positive no-child WTS result and independent session enumeration. Error 1168, unexpected `TermService`/listener change, a new guest/tunnel route, source failure or fingerprint drift is a stop and reviewed restoration, not permission to connect.

Only after Stage A succeeds and **separate Stage B approval** for the same SHA/hash and one local loopback connection, use [Stage B's `approve-b-boundary` and `connect-once-boundary` commands](isolated-stage-b.md#separate-approval-and-preflight) in the existing journal. Observe both physical and child desktops responding independently to alternating harmless input, focus changes, viewer minimize/restore and continued physical-console use. Record the exact parent-associated child ID and WTS logon generation privately. Do not infer success from a child ID alone. Closing the viewer is not child sign-out.

With a **separate exact-child teardown approval**, use [Stage B's identity-bound teardown](isolated-stage-b.md#exact-teardown-and-restoration), restore the original child-feature value, and require `ReconnectReady=True` before any network restoration. Never target an unrelated Windows session. An interrupted viewer, uncertain identity, ambiguous logoff or changed listener uses the [reviewed Stage B recovery path](isolated-stage-b.md#interrupted-viewer-or-changed-boundary) and the [physical-console `TermService` recovery path](external-boundary-stage-a.md#unexpected-termservice-or-rdp-listener-after-feature-enablement); keep the PC physically offline until exact child absence, feature restoration and original RDP/service/listener state are independently verified. Preserve the journal on conflict; do not retry an ambiguous operation.

Only after the reconnect check and local review, restore the recorded physical links. If Tailscale was originally connected, run `tailscale up` without flags after external connectivity returns, then compare its profile, status, service, tunnel address/routes and unattended behavior with the private original record. Restore only previously running Docker/WSL work through owner-approved commands and verify each project's data and health. Compare final RDP, firewall, Sunshine, VDD and display observations with the original. A failed Tailscale reconnect or workload restoration is a recovery issue to resolve, not evidence that the child-session test succeeded.
