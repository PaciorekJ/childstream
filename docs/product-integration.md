## Pinned Sunshine release

Selected official stable release: `v2026.914.233613`, Windows AMD64 **lite** ZIP, 38,060,196 bytes. The release asset SHA-256 is `233008e46f4c0e501a586cbfd6c4fd4a4c0d414a0b5fc7f13c070eb92ec3824b`; its `Sunshine/sunshine.exe` SHA-256 is `a8ddf74e93297529ca5aa9c59234a7043b94587e8d11ea24c521fa69d6f59fd3`. The downloaded archive and executable were checked read-only against these pins. Windows reports the executable **NotSigned**; no publisher-signature claim is made. The package validator requires the exact versioned official URL, pinned archive bytes, pinned executable bytes and expected layout before extraction. A release change requires new independently reviewed pins and format tests. The lite build's behavior and performance in a child session are unverified. [Official release](https://github.com/LizardByte/Sunshine/releases/tag/v2026.914.233613), [configuration reference](https://docs.lizardbyte.dev/projects/sunshine/latest/md_docs_2configuration.html).

Sunshine's documented first command-line argument selects a full config-file path. The candidate config isolates apps, state, credentials, log, certificate and key under the exact child session directory. `output_name` requires the display `device_id` seen from the child, while `dd_configuration_option=verify_only` and disabled resolution/refresh changes avoid silently modifying the physical display. Windows `wgc` is a portable-only beta capture backend; `ddx` is the alternate. The selected backend and NVENC must be confirmed from child-side logs. The free `vigembus` backend supports only limited Xbox 360/DS4 emulation and is end of life; a paid Virtual HID license is not assumed. [Official configuration reference](https://docs.lizardbyte.dev/projects/sunshine/latest/md_docs_2configuration.html).

The current code accepts only `127.0.0.1` at the documented default base port 47989. Published port-family offsets are checked conservatively for startup collisions and runtime listener ownership. A real Fire TV stream needs a separate approved LAN bind, port-family and firewall design; custom-port Moonlight compatibility is not assumed. An existing `SunshineService`, another Sunshine process or an occupied family port blocks startup. The current code never stops that service or edits its config. A no-NIC Stage A/B test cannot establish Fire TV streaming.

## Installer and recovery scope

The file adapter supports newly created, small ChildStream-owned files only. It refuses existing unowned files and registry/firewall/service/driver/Windows-session resources. The transaction engine durably records the plan and exact original absence before writes. Rollback uses a no-share handle to compare bytes before deleting the exact file. Changed or unexpected files stop recovery, preserving evidence and other owners. The large portable archive has its own versioned, checksummed extraction manifest flushed before creating the version directory; recovery validates every path and digest before deleting exact files. Unknown files, reparse points or missing journal information stop recovery. This source does **not** install or remove native Sunshine or VDD.

`setup.ps1` remains deliberately disabled for live Apply, Recover and Uninstall. A safe production adapter still needs an accepted child bootstrap, approved LAN posture, restricted credentials/pairing storage, installer orchestration across the small-file and archive journals, and a live fault-injection rollback test on independent Windows hardware. No journal or package test here proves those gates. Steam commands are issued only by a process already verified inside the child; any parent or unrelated Steam instance blocks launch. A returned Steam launch-request PID is not accepted as proof that Minecraft Dungeons started.
