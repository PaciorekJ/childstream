The protected workstation and its unrelated development resources are outside this implementation's test scope. The code in this increment is source and offline evidence, not a working Fire TV stream. No Windows feature, service, network setting, native Sunshine/VDD installation, Docker/WSL workload, Steam account or game was changed.

That path has substituted-boundary evidence only and cannot be used from a phone or Fire TV while the runtime stays on loopback.

## Pinned Sunshine release

Selected official stable release: `v2026.914.233613`, Windows AMD64 **lite** ZIP, 38,060,196 bytes. The release asset SHA-256 is `233008e46f4c0e501a586cbfd6c4fd4a4c0d414a0b5fc7f13c070eb92ec3824b`; its `Sunshine/sunshine.exe` SHA-256 is `a8ddf74e93297529ca5aa9c59234a7043b94587e8d11ea24c521fa69d6f59fd3`. The downloaded archive and executable were checked read-only against these pins. Windows reports the executable **NotSigned**; no publisher-signature claim is made. The package validator requires the exact versioned official URL, pinned archive bytes, pinned executable bytes and expected layout before extraction. A release change requires new independently reviewed pins and format tests. The lite build's behavior and performance in a child session are unverified. [Official release](https://github.com/LizardByte/Sunshine/releases/tag/v2026.914.233613), [configuration reference](https://docs.lizardbyte.dev/projects/sunshine/latest/md_docs_2configuration.html).

Sunshine's documented first command-line argument selects a full config-file path. The candidate config keeps Sunshine state, credentials, certificate and key in a stable private ChildStream identity directory; apps, config and logs are scoped to the exact child generation. `output_name` requires the display `device_id` seen from the child, while `dd_configuration_option=verify_only` and disabled resolution/refresh changes avoid silently modifying the physical display. Windows `wgc` is a portable-only beta capture backend; `ddx` is the alternate. The selected backend and NVENC must be confirmed from child-side logs. The free `vigembus` backend supports only limited Xbox 360/DS4 emulation and is end of life; a paid Virtual HID license is not assumed. [Official configuration reference](https://docs.lizardbyte.dev/projects/sunshine/latest/md_docs_2configuration.html).

The configuration builder retains its loopback default. The normal application's LAN action stops and reconciles its exact local Sunshine process, retains the child and pairing identity, and starts a separate generation-scoped LAN configuration after a protected plan is admitted. The pinned release has one global bind address: LAN mode binds `0.0.0.0`; two Private-profile rules target only the pinned ChildStream executable and exclude the web administration port. The child agent rechecks the boundary on commands and by a timer while the UI is idle, withdrawing the exact process on drift. The Windows adapter checks exact hardware identity, the selected interface's Private profile and every other active IPv4 profile, local-rule effectiveness, profile-specific interface exclusions, block-all state and overlapping inbound blocks. It converts CIM network categories to the distinct firewall profile-bit values; raw policy-surface fixtures verify each getter index. Ambiguous readings fail closed. These source checks do not establish effective WFP/GPO containment or Moonlight reachability on an actual network. A native `SunshineService` is preserved; two-instance behavior, Fire TV custom-port compatibility and concurrent capture require independent live evidence. [Pinned Sunshine network source](https://raw.githubusercontent.com/LizardByte/Sunshine/v2026.914.233613/src/network.cpp), [Sunshine multiple-instance caution](https://docs.lizardbyte.dev/projects/sunshine/v0.19.0/about/usage.html).

## Installer and recovery scope

The file adapter supports newly created, small ChildStream-owned files only. It refuses existing unowned files and registry/firewall/service/driver/Windows-session resources. The transaction engine durably records the plan and exact original absence before writes. Rollback uses a no-share handle to compare bytes before deleting the exact file. Changed or unexpected files stop recovery, preserving evidence and other owners. The large portable archive has its own versioned, checksummed extraction manifest flushed before creating the version directory; recovery validates every path and digest before deleting exact files. Unknown files, reparse points or missing journal information stop recovery. This source does **not** install or remove native Sunshine or VDD.

`setup.ps1` remains a disabled legacy entry point. The unsigned candidate includes and installs `ChildStreamBootstrap.exe`; read-only `-plan` checks an independently supplied candidate ZIP digest and pinned Sunshine archive. `-apply`, `-repair` (intact verification), `-recover` and `-uninstall` require a separately elevated physical-console invocation. The normal app presents install, installed-app handoff and maintenance controls. Its installed-app maintenance path uses an external bootstrap from an identically reviewed candidate, exits, and makes the helper wait for that app PID before reversal. If the original archive is gone, a reacquired identical archive and matching extracted bootstrap can be selected after verifying the same independently reviewed SHA-256. The fixture demonstrates recovery/new-plan/reapply after an owned file is missing; foreign drift remains preserved. This still needs a signed, immutable bootstrap trust model and live UAC, installed-process-exit and rollback acceptance. Pairing identity and protected rollback records remain by default; full removal of tasks, LAN rules and retained data is not implied by file reversal. The scoped setup helper separately plans/applies/reverses LAN and feature transactions under explicit approval. Steam commands are issued only by the verified child agent, and delayed game observation is recorded durably before cleanup.
