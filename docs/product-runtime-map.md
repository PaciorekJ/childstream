# Product runtime map — integrated software candidate

```text
ordinary Windows user -> ChildStream.exe (asInvoker)
  -> first-run feature/token observation -> explicit setup dialog
       -> read-only connected-LAN plan via one short-lived UAC helper
       -> separately approved begin / feature preparation / exact restoration
       -> existing feasibility plan hash, private journal, drift and rollback gates
  -> explicit demand-only interactive-token child-agent task registration
  -> ActiveX loopback child viewer -> exact WTS child identity and generation
  -> RunEx request -> verified limited agent PID/image/token + bounded named pipe
       -> typed status / owned Sunshine / pairing / Steam / fixed game operations
       -> stable per-user Sunshine certificate, state and DPAPI admin credential
       -> generation-scoped process records, configuration and logs
```

The normal application does not request elevation for launch, pairing or
reconnect. Its setup helper accepts a fixed operation set, checks the requesting
limited process and physical console, displays the requester and approving
Administrator identities, and uses the existing connected-network probe
transaction. The protected workstation's current 20 potentially permissive and
six unknown RDP firewall rules still reject that plan. A helper receipt or
previous journal never proves the current feature state.

The task adapter is a separate, explicit current-user action. It creates only
a demand-only, limited interactive-token task for that SID and exact protected
`ChildStream.exe` action; runtime checks its definition again before `RunEx`.
No task was registered during development. Scheduler behavior with an actual
child session and an over-the-shoulder Administrator approval remains physical
acceptance work.

The child agent now executes typed operations and rejects arbitrary paths or
shell commands over its pipe. Sunshine uses a separate versioned executable,
exact process/listener checks, private stable pairing identity, a certificate-
pinned local HTTPS API and explicit PIN approval. Steam/game commands use fixed
paths discovered inside the limited child, reject an existing parent or foreign
Steam singleton, and require exact process observations for teardown. An
unobserved game launch remains uncertain and blocks destructive cleanup.

The current runtime Sunshine configuration binds only to loopback. A phone or
Fire TV cannot connect through that mode; the existing distinct-port LAN
candidate is not a production authorization or firewall plan. GPU capture,
native Sunshine coexistence, child-only controller input, audio independence,
LAN Moonlight and gameplay remain unverified. The unsigned candidate is not
installed and does not contain Sunshine. No Stage A/B or host mutation occurred.
