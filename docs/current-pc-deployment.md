# Recommended current-PC deployment

**Selected arrangement:** one Windows parent console plus its exact parent-associated loopback child session; a limited ChildStream agent, portable ChildStream-owned Sunshine, Steam and the game run inside that child. The existing native Sunshine service, VDD and parent desktop remain owned by their current operators. Moonlight on Fire TV or phone connects only to the ChildStream port family after a separate LAN plan is approved. This is the single-PC product path, conditional on real Stage A/B and resource tests; it is not an accepted deployment on the intended workstation today.

| Requirement | Supported enforcement in this arrangement | What remains unproved or blocked |
| --- | --- | --- |
| Independent desktop | Windows [child sessions](https://learn.microsoft.com/en-us/windows/win32/termserv/child-sessions) create a separate loopback RDP session tied to the parent. ChildStream verifies the associated WTS ID and logon generation and keeps the ActiveX viewer alive. Sunshine and the child agent must run in that exact session. | The intended host reports the feature disabled. No Stage A/B has run. A child session is a desktop boundary, not a separate machine or security boundary for files and devices. |
| Host resources | Both sessions share the PC's Windows installation, GPU and installed applications. ChildStream's limited agent and exact process ownership confine what ChildStream itself starts/stops; no GPU passthrough or file copy is required. | Child GPU capture/NVENC, concurrent native Sunshine capture, Steam singleton behavior and game licensing need real acceptance. Same-user access does not isolate unrelated files or services. |
| Controller input | Pinned Sunshine supports a fixed Windows ViGEmBus-only Xbox 360 choice. Production and discovery configurations explicitly select that free backend and suppress controller reports until actual cross-session isolation is established; discovery also disables keyboard/mouse. In the interactive child, Sunshine's keyboard/mouse path remains available. | ViGEm target identity and feeder ownership do not restrict parent consumption. PnP enumeration, permission to read a report and observed cross-session input are different facts. The two-session controlled input test in [controller-routing](controller-routing.md) is required before enabling gamepads; no current code claims that acceptance. |
| Audio | Before each connection, ChildStream sets documented [RDP playback mode 1](https://learn.microsoft.com/en-us/windows/win32/termserv/imsrdpclientsecuredsettings-autoredirectionmode) for remote-computer playback and [microphone redirection false](https://learn.microsoft.com/en-us/windows/win32/termserv/imsrdpclientadvancedsettings7-audiocaptureredirectionmode). Its exact child agent selects an active endpoint ID, then starts the pinned Sunshine with `external_audio = enabled`, `stream_audio = disabled`, and that exact `audio_sink`. After the exact game is observed rendering there, the owner explicitly triggers an exact-owned Sunshine restart with `stream_audio = enabled`. The idle monitor withdraws it if route evidence is lost. Neither a Windows default writer nor audio-driver installer is invoked. | An active endpoint ID is not proof that the game renders there or that the endpoint is inaccessible to the parent. A nondefault endpoint needs a separately established application/external-mixer route. The polling interval cannot rule out transient leakage or agent failure. Simultaneous game/Moonlight/parent audio acceptance remains unrun; this configuration is rejected if parent audio is affected. |
| Network containment | Local startup uses loopback. A separately approved LAN transaction scopes the pinned Sunshine executable, selected Private physical interface, subnet and streaming ports; UPnP and driver auto-install are disabled. The child agent verifies process/listener identity and withdraws its owned stream on boundary drift. Pairing pins its owned certificate. A separate protected setup transaction now plans, applies, reads back, and exactly recovers two ChildStream-owned TermService inbound blocks for non-loopback TCP and UDP traffic across all profiles and ports. | The Sunshine LAN configuration has a wildcard IPv4 listener, so effective Windows firewall/WFP behavior and custom Moonlight port access need physical testing. The RDP blocks have source and ActiveStore checks, but their actual packet behavior, child loopback compatibility, virtual guest paths, and current-host policy are untested. Existing potentially permissive/unknown RDP rules keep connected-host Stage A No-Go until independently qualified containment. |
| Least privilege and recovery | Standard-user app and child agent; one demand-only current-user task; scoped elevated setup helper only for separately approved protected changes. Durable exact-owned files, process identities and transaction journals support stop, recovery and rollback without touching native Sunshine or VDD. | No real UAC, feature enablement, task registration, rollback, child start or Sunshine execution has run. Fresh parent sign-in may be a one-time first-enable requirement; it is not a normal stream or pairing step. |

The controller path is deliberately a selected **configuration with an unpassed acceptance gate**, not a virtual-controller implementation. Sunshine remains the only streaming/input engine. The pinned [Sunshine configuration](https://docs.lizardbyte.dev/projects/sunshine/master/md_docs_2configuration.html) supports the explicit gamepad driver, controller, audio sink, display and network settings used here. A live child-only gamepad claim requires parent and child observers plus the actual game input API; the presence of a PnP device or a successful software fixture cannot substitute for it. If the parent consumes child controller reports, this configuration is rejected. Parent desktop, input and audio noninterference are requirements, not negotiable acceptance criteria.

The newly pinned [Sunshine Windows audio implementation](https://github.com/LizardByte/Sunshine/blob/178a0467da1dde750b182be4ae10ff8f8245ad01/src/platform/windows/audio.cpp) has an `external_audio` branch that pins the selected sink and avoids default-device switching, format changes, and automatic Steam audio-driver installation. The exact official prerelease binary and upstream policy tests are identified in [audio candidate delivery](audio-candidate.md). Sunshine does not route game playback into the sink; the game or an external router must do that. A child-observed endpoint may still be shared with the parent. If simultaneous listening shows parent effects, reject this deployment.

**Current-PC stop condition:** do not enable child sessions while the connected-network RDP posture lacks independently qualified containment, and do not require a parent sign-out that interrupts protected work. The source-only containment transaction does not itself supply that live qualification; the shipping connected feature path refuses a feature write even after ActiveStore readback. A VM on this Windows 11 Pro PC is not the selected deployment; no VM creation is authorized. If the two-session controller test shows parent consumption, reject this configuration. If audio separation fails, reject it until a verified child-only render route exists. Do not add a custom driver, game hook or privileged service by default.

## One bounded, unexecuted Windows qualification proposal

This proposal creates no authority to run commands. The elevated, read-only host result is `ChildSessionsEnabled=False`. The connected-network baseline has 20 potentially RDP-permissive and six unknown firewall rules; there is **no accepted exact plan hash** and no proven containment of a listener that feature enablement might create. The source now supplies a narrowly scoped, separately approved local firewall transaction: two inbound TermService block rules, one TCP and one UDP, all local ports and all profiles, with remote IPv4 127/8 and IPv6 ::1 excluded. It verifies the exact persistent and ActiveStore rule filters, profile merge/enabled/exclusion policy, no authenticated bypass allow, ordinary RDP denial, feature state, and TermService/listener baseline. It records an exact private requester journal before any write and retains protection until the original feature, service and listener observations return. It does **not** claim the packet split works on this Windows host: IPv4-mapped IPv6, service attribution, WFP ordering, guest forwarding, and local child connection behavior need a separately authorized live qualification. No feature write can proceed on readback alone. Existing Sunshine, VDD, networking and protected workloads remain untouched.

After that gate passes and the owner separately approves an exact plan hash, the bounded Stage A effect would be one journaled machine-wide `WTSEnableChildSessions(true)` from observed False, read-only feature/WTS/listener verification at the physical console, and exact restoration to False. Ordinary network RDP must stay denied throughout; stop immediately on unexpected TermService/listener changes, error 1168, ambiguous feature state, or journal drift. Do not reconnect or remove a temporary containment measure until the feature and listener baseline are independently restored. A failed restore leaves containment in place for reviewed recovery, without further child creation.

Microsoft's [child-session documentation](https://learn.microsoft.com/en-us/windows/win32/termserv/child-sessions) describes an automatic-authentication exception when the parent logged on before enablement. Test the API result first; a fresh parent sign-in is a possible one-time setup step, never a routine launch or Moonlight-pairing step. On this protected workstation, if the experiment requires sign-out or fresh sign-in that would interrupt unrelated work, stop and restore without signing out. A separately approved Stage B would permit one loopback viewer connection, simultaneous parent/child desktop interaction checks and exact-child teardown under the same verified containment, followed by independent feature/listener restoration. Controller, audio and GPU/streaming tests follow only if Stage B passes and each parent-noninterference gate is separately met.
