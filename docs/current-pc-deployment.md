# Recommended current-PC deployment

**Selected arrangement:** one Windows parent console plus its exact parent-associated loopback child session; a limited ChildStream agent, portable ChildStream-owned Sunshine, Steam and the game run inside that child. The existing native Sunshine service, VDD and parent desktop remain owned by their current operators. Moonlight on Fire TV or phone connects only to the ChildStream port family after a separate LAN plan is approved. This is the single-PC product path, conditional on real Stage A/B and resource tests; it is not an accepted deployment on the intended workstation today.

| Requirement | Supported enforcement in this arrangement | What remains unproved or blocked |
| --- | --- | --- |
| Independent desktop | Windows [child sessions](https://learn.microsoft.com/en-us/windows/win32/termserv/child-sessions) create a separate loopback RDP session tied to the parent. ChildStream verifies the associated WTS ID and logon generation and keeps the ActiveX viewer alive. Sunshine and the child agent must run in that exact session. | The intended host reports the feature disabled. No Stage A/B has run. A child session is a desktop boundary, not a separate machine or security boundary for files and devices. |
| Host resources | Both sessions share the PC's Windows installation, GPU and installed applications. ChildStream's limited agent and exact process ownership confine what ChildStream itself starts/stops; no GPU passthrough or file copy is required. | Child GPU capture/NVENC, concurrent native Sunshine capture, Steam singleton behavior and game licensing need real acceptance. Same-user access does not isolate unrelated files or services. |
| Controller input | Pinned Sunshine supports a fixed Windows ViGEmBus-only Xbox 360 choice. Production and discovery configurations explicitly select that free backend and suppress controller reports until actual cross-session isolation is established; discovery also disables keyboard/mouse. In the interactive child, Sunshine's keyboard/mouse path remains available. | ViGEm target identity and feeder ownership do not restrict parent consumption. PnP enumeration, permission to read a report and observed cross-session input are different facts. The two-session controlled input test in [controller-routing](controller-routing.md) is required before enabling gamepads; no current code claims that acceptance. |
| Audio | Sunshine's documented audio_sink selects one exact child-observed render endpoint; ChildStream does not change the system default or auto-install Steam audio drivers. Windows RDP supports audio redirection settings through the [ActiveX control](https://learn.microsoft.com/en-us/windows/win32/termserv/imsrdpclientsecuredsettings-autoredirectionmode). | Enumerating an endpoint inside the child does not prove only the child uses it. Default RDP audio redirection can play child sound through the parent, and a shared physical sink could capture parent sound. Require a verified distinct child render path and simultaneous parent/child listening test. If absent, the smallest established alternative is an operator-approved separate audio endpoint with per-app routing, subject to its own noninterference test; do not silently install or globally switch a driver. |
| Network containment | Local startup uses loopback. A separately approved LAN transaction scopes the pinned Sunshine executable, selected Private physical interface, subnet and streaming ports; UPnP and driver auto-install are disabled. The child agent verifies process/listener identity and withdraws its owned stream on boundary drift. Pairing pins its owned certificate. | The Sunshine LAN configuration has a wildcard IPv4 listener, so effective Windows firewall/WFP behavior and custom Moonlight port access need physical testing. The LAN rules do not contain a TermService listener. Existing potentially permissive/unknown RDP rules keep connected-host Stage A No-Go. |
| Least privilege and recovery | Standard-user app and child agent; one demand-only current-user task; scoped elevated setup helper only for separately approved protected changes. Durable exact-owned files, process identities and transaction journals support stop, recovery and rollback without touching native Sunshine or VDD. | No real UAC, feature enablement, task registration, rollback, child start or Sunshine execution has run. Fresh parent sign-in may be a one-time first-enable requirement; it is not a normal stream or pairing step. |

The controller path is deliberately a selected **configuration with an unpassed acceptance gate**, not a virtual-controller implementation. Sunshine remains the only streaming/input engine. The pinned [Sunshine configuration](https://docs.lizardbyte.dev/projects/sunshine/v2026.914.233613/md_docs_2configuration.html) supports the explicit gamepad driver, controller, audio sink, display and network settings used here. A live child-only gamepad claim requires parent and child observers plus the actual game input API; the presence of a PnP device or a successful software fixture cannot substitute for it.

**Current-PC stop condition:** do not enable child sessions while the existing connected-network RDP posture lacks containment, and do not require a parent sign-out that interrupts protected work. A VM on this Windows 11 Pro PC is not a default gaming substitute: Microsoft's [supported Hyper-V GPU assignment guidance](https://learn.microsoft.com/en-us/troubleshoot/windows-server/virtualization/troubleshoot-hyper-v-gpu-assignment-partitioning-passthrough-issues) excludes client Windows 11 Pro and desktop-class GPU-P/DDA. No VM creation is authorized. If the two-session controller test shows parent consumption, no supported same-PC configuration in the selected stack has been established. The smallest owner decision is whether parent controller noninterference remains mandatory; if it does, select a separately supported Windows device boundary for the game rather than adding a custom driver or hook. If audio separation fails, choose an existing dedicated endpoint with verified per-app routing or authorize one supported audio-device installation separately. Neither alternative is presumed available on this PC.
