## Permanent scope boundary

The [scope boundary](scope-boundary.md) forbids inspecting or interrupting unrelated development environments and forbids changing shared Docker Desktop, WSL2, Tailscale or networking to make ChildStream pass. This is not a pending workload-owner approval. The prior workload-pause runbook is retired and the cross-project workload collector is removed. Previously collected private evidence is historical only and is not an action list or a reason to reinspect protected resources.

**Stage A/B on the shared workstation through workload quiescence and physical disconnection is blocked.** The v5 gate must keep rejecting active guest paths, unattributed addressed tunnels and uncertain RDP exposure. The connected-network firewall gate also stays unchanged. Do not relabel these findings or weaken the gate to force an accepted plan.

1. No independent Windows test environment is currently available. A borrowed compatible Windows 11 Pro PC or a disposable no-NIC Generation 2 VM on an **independent, existing** virtualization host are the no-purchase options if one can actually be obtained. A dedicated PC is the fallback for physical GPU/streaming tests. A VM on the protected workstation is not authorized or demonstrated noninterfering. See the [environment requirements](independent-test-environment.md) and [independent target procedure](stage-ab-physical-window.md).
2. On an independent target, follow the [single acceptance kit](independent-acceptance-kit.md): transfer the exact source, run the offline suite, take a private original-state inventory, verify Basic Session Mode or physical console protocol 0 and offline sign-in/recovery, and run only a read-only plan. A new strict v6 plan may work in a truly no-network VM without requiring absent Hyper-V/Docker/HNS tooling to masquerade as successful empty reads. The v5 plan can be used on a dedicated physical lab PC only if every source and predicate actually passes.
3. Obtain separate approval of the exact plan hash for one Stage A feature/logon cycle. A positive WTS no-child result allows consideration of Stage B; error 1168, session ambiguity, listener drift or restoration failure is a stop with journal-preserving recovery.
4. The one-window strict-isolation v6 journal and commands are implemented and offline-tested. Separate Stage B consent, sustained viewer, durable exact-child identity, interrupted-attempt reconciliation, exact-child teardown and reviewed restoration are present. Old v4 journals remain readable and Stage A only; v5 remains intact. The [strict Stage B procedure](strict-isolated-stage-b.md) applies only after independent target evidence and separate approvals. All Stage B paths are live-unverified.
5. After a positive independent desktop test, resolve exact child process bootstrap, validate GPU/display in the lab, then Sunshine/Moonlight, Fire TV, controller/audio separation, Steam/gameplay, installer/recovery and final acceptance. The source currently refuses to infer that a child process can be created or a parent Steam singleton can be reused safely. A VM result cannot qualify physical GPU capture or the protected workstation. Any later test there needs a new coexistence design that preserves active workloads and contains an unexpected ordinary RDP listener without relying on their interruption.

The next meaningful outcome is a separately authorized test on independent Windows hardware, or an explicit technical blocker in that target. No host mutation is authorized by this ledger.
