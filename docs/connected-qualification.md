# Connected feature setup: qualification and recovery boundary

This path is source-complete for a first, separately approved Stage A feature operation. It has **not** qualified the intended workstation. The independently measured packet evidence and child-session behavior below are still missing. ChildStream never signs out the parent automatically.

## Two evidence stages

1. **Before feature enablement:** A separate approval applies the two exact ChildStream-owned, non-loopback inbound TermService block rules. The normal setup form then makes a version 7 connected plan. A read-only Windows Security log query looks for recent inbound WFP 5152/5157 drops on the configured RDP port, with `FilterOrigin` equal to each exact owned TCP/UDP rule. Every active, independently attributable physical external interface needs both protocols. Any addressed virtual, tunnel, or other interface whose path cannot be attributed rejects qualification. The helper verifies the original feature is disabled, ordinary-RDP policy denies connections, listeners are absent, owned rules are effective in ActiveStore, and the probe plan and network/firewall fingerprints agree. A closed socket or a rule's mere presence does not count as a packet drop.
2. **After a new, separate feature-operation approval:** The helper consumes that exact reviewed record before creating the probe journal. A further exact-plan approval is required for `PrepareFeature`; it performs at most one journaled `WTSEnableChildSessions(true)` attempt. The operator may need a one-time fresh physical-console sign-in. `VerifyStageA` separately checks the actual WTS no-child result and unchanged policy, listener, network and owned-rule state. Error 1168 or a changed listener is not a positive result. A real child-loopback desktop connection needs **another** Stage B approval and observation; it cannot be required as pre-enable proof.

The pre-feature record includes Windows MachineGuid, requesting-account hash, Windows build, exact containment journal and feature plan hashes, original network/firewall fingerprints, active interface identities/addresses, Security event record IDs and timestamps, and a ten-minute expiry. The helper stores it only in the protected requester directory. `Capture packet proof` records a pending hash; `Review proof hash` requires independent human review of that exact hash. `Begin approved plan` and `Enable feature` re-read the native event records and current state, reject replay and drift, and never accept a user-supplied Boolean as packet proof. The standalone connected feasibility CLI has no new mutating entry; its old connected mutation commands are refused. Its legacy restore path remains for historical recovery.

## Stop and restoration

If capture or review fails before `Begin approved plan`, the feature is still disabled and there is no feature journal. Leave the containment rules in place while inspecting the reason; retire an exact pending/reviewed record under the current closed-RDP baseline, then separately recover the owned rules if desired. After a begun plan, inspect the requester journal. If feature enablement is ambiguous or a listener/service changes, retain containment and use reviewed exact-state recovery. `Restore original` checks child absence and the original feature state before marking the probe journal restored. Only then can the exact qualification record be retired and the owned rules removed. Interrupted retirement is retried only against identical private bytes; a conflicting copy blocks. Uninstall refuses active qualification, containment, or unrestored probe journals.

## Current qualification limit

The pre-feature WFP events are not known to exist on the intended PC. The owned rules are scoped to **TermService**, while ordinary RDP policy denies connections and the current baseline has no RDP listener. A remote connection failure to an absent listener does not prove these rules blocked the packet. Windows may produce no attributable 5152/5157 record until a TermService endpoint exists. The helper does not enable auditing, ordinary RDP, or a test listener to manufacture proof. Its current native path classifier also rejects any active addressed virtual/tunnel interface rather than claiming guest-path coverage it cannot verify. This includes the known protected-workstation topology. Consequently **no connected Stage A feature write is admitted there by current evidence**. A narrower independently qualified path or a separate Windows target remains necessary. Stage B, GPU, Sunshine, controller, audio and Fire TV behavior remain physically unverified.

Microsoft documents Windows 11 WFP 5152/5157 `Filter Origin` and `Interface Index` fields in its [filter-origin audit documentation](https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/filter-origin-documentation). Its documentation also states that auditing those events may require enabling the relevant audit policy. ChildStream does not change that policy automatically.
