# Minimum independent Windows test environment

No independent Windows machine is currently available. The protected development workstation is the intended eventual product target, but ChildStream may not provision a VM on it, interrupt its workloads, change its networking, or use a workload pause as an acceptance prerequisite. The existing physical-host Stage A/B path is blocked by that scope boundary. This page describes what another environment could prove; it authorizes no procurement or host change.

## Least disruptive options

1. **Borrow or temporarily use an existing, independently owned compatible PC.** This is the first no-purchase option if one becomes available. It needs its own console, storage, Windows 11 Pro installation and recovery access. Its owner must approve each mutating test. Source transfer and offline tests precede any feature action. It can prove child-session APIs and physical desktop interaction. Its GPU/Fire TV results apply to that hardware only.
2. **Use a disposable no-NIC Windows 11 Pro VM on a separate existing virtualization host.** This avoids purchase only if such a host and licensed guest are already available. It can test WTS feature enablement, fresh logon, exact child identity, one interactive viewer, teardown and rollback. The host must have a direct console path to VMConnect Basic Session Mode; an RDP-only cloud guest does not establish protocol-0 parent-console evidence. A VM with virtual graphics cannot qualify physical GPU capture, VDD, controller/audio routing or Fire TV performance.
3. **Use a dedicated Windows 11 Pro PC** if neither independent resource can be obtained. This is the smallest credible path to physical GPU/display and streaming evidence. It is not a substitute for later coexistence validation on the intended workstation.

Windows Sandbox, dual boot, and a VM on the protected workstation share its CPU, RAM, storage, virtualization state or boot availability. No evidence currently proves they can run without affecting protected work; the user has specifically disallowed VM provisioning there. A cloud guest reached only over ordinary RDP is not a protocol-0 guest-console test. Do not call any of these a validated no-purchase solution.

## Minimum capability by test

| Test | Minimum environment | What remains unproved |
| --- | --- | --- |
| Stage A feature and WTS API | Windows 11 Pro build 22000 or later, console protocol 0, local recovery access, isolated networking, offline sign-in, already elevated same-account process for the feature write | Independent child desktop and product streaming |
| One Stage B interaction | The above plus separately approved v6 strict-isolation plan, a second console observer, working local ActiveX control and exact-child recovery access | GPU, audio, controller and game behavior |
| GPU/display and Sunshine capture | Physical Windows PC with usable supported GPU, display path and a separately reviewed Sunshine setup | Fire TV quality and target-workstation coexistence unless tested there |
| Fire TV/gameplay acceptance | Physical gaming PC and Fire TV on a reviewed scoped network, real controller/audio/game checks, parent desktop usability | Protected workstation acceptance if performed on another PC |

For **a standalone Windows 11 Pro API test PC**, Microsoft's installation floor is a supported 64-bit processor with at least two cores at 1 GHz, 4 GB RAM, 64 GB storage, UEFI/Secure Boot capability and TPM 2.0. These are OS minimums, not a claim that a 4 GB machine is suitable for gaming or concurrent streaming. A practical isolated Stage A/B target is four CPU cores, 8 GB RAM, at least 128 GB free or dedicated SSD capacity, a local display and keyboard, and a verified offline sign-in method. The exact GPU requirement for Sunshine/gameplay must be chosen from the intended encoder, display and game workload and validated on hardware; this API test does not establish it. [Windows 11 requirements](https://learn.microsoft.com/en-us/windows/whats-new/windows-11-requirements).

For **an independent Hyper-V VM host**, Microsoft requires Windows Pro/Enterprise or supported Windows Server, a 64-bit CPU with SLAT and VM monitor extensions, firmware virtualization and hardware DEP enabled, plus enough RAM for host and guest. Windows 11 guests require Generation 2, at least two vCPUs, 4 GB RAM, 64 GB disk, Secure Boot and virtual TPM. The practical proposed guest is four vCPUs, 8 GB RAM and at least 64 GB disk **in addition to** host reserves; host resources must be measured before use. Attach no guest NIC during Stage A/B, take a pre-mutation checkpoint, and verify VMConnect Basic Session Mode and guest protocol 0. Enhanced Session Mode uses RDP and does not satisfy this console prerequisite. [Hyper-V host requirements](https://learn.microsoft.com/en-us/windows-server/virtualization/hyper-v/host-hardware-requirements), [Windows 11 VM requirements](https://learn.microsoft.com/en-us/windows/whats-new/windows-11-requirements), [VMConnect session modes](https://learn.microsoft.com/en-us/windows-server/virtualization/hyper-v/enhanced-session-mode).

The Windows 11 Pro installation and local sign-in must be prepared before the no-NIC test; Microsoft-account-dependent setup or recovery must not strand the operator offline. An approved guest image/license and original-state snapshot are prerequisites, not assumptions. A passing read-only `plan-isolated` is still required on the exact guest or PC. An unavailable environment, ambiguous network observation or error 1168 is a stop, not acceptance.

## Current decision

Neither independent option has been demonstrated available. Continue source implementation and offline/CI qualification. The first live child-session API result, independent desktop interaction, GPU/display access, Sunshine capture, Fire TV, controller/audio, Steam/gameplay, installer live recovery and final workstation coexistence **remain unverified**. No dedicated hardware purchase is authorized or assumed. The next environment decision is to identify or obtain an independent physical PC or independent Hyper-V console host, then run read-only qualification before separately approving any mutation.
