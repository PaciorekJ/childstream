# Permanent ChildStream scope boundary

The operator's elevated read-only API result on 2026-10-15 confirms the child-session feature was disabled on the intended workstation at observation time. Enabling it would be a machine-wide change. The connected-LAN route is also blocked: the existing RDP/firewall assessment has 20 potentially permissive and six unknown inbound rules for a hypothetical listener, and the current parent logon predates any enablement. No plan hash or noninterfering fresh-logon path has been established. The result does not permit a connected-LAN feature experiment.

ChildStream work must not inspect, modify, stop, restart, back up, remove, reconfigure or depend on interruption of unrelated repositories, development environments, containers, databases, volumes, services, credentials or active processes. This includes the protected development workloads previously mentioned in ChildStream planning. Docker Desktop, WSL2, Tailscale and shared host networking must remain available to their existing users. This is an architectural constraint, not a request for their owners to approve a pause or assume a ChildStream recovery duty.

The shared Windows workstation's v5 external/guest isolation gate presently fails with active internal guests and an addressed tunnel. Its firewall findings remain unchanged. **Physical-host Stage A/B through network disconnection or workload quiescence is blocked.** Do not run `plan-boundary` as a prelude to changing protected resources, and do not relax `GuestPath`, virtual-path attribution, RDP or connected-network gates to make the result pass. Historical read-only captures establish why that path is blocked; do not recollect unrelated workload details for ChildStream.

Use a separately provisioned Windows test machine with no protected workloads as the preferred next target. A disposable Windows 11 Pro VM on an **independent** virtualization host may establish child-session API and interaction feasibility before a dedicated physical test. A VM on the protected workstation is not assumed independent: its CPU, RAM, storage and Hyper-V activity can affect existing work even with its NIC disconnected. It requires a separate resource-impact assessment and authorization and is not the default path. VM results cannot certify the target workstation GPU, display, Sunshine capture, controllers, audio or Fire TV performance.

No new host mutation is authorized by this document. Any test environment must have its own original-state record, isolated network, recovery access, exact-source offline tests and separate approval for feature enablement, sign-out, Stage B child creation and teardown. Real product acceptance on a shared workstation would additionally need a proven, narrowly scoped coexistence design that preserves all existing services and contains any unexpected RDP listener without relying on stopping them. Until such a design is implemented and independently validated, classify that target-host acceptance as blocked rather than complete.
