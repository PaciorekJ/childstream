# Proposed operator-controlled WSL and Docker pause for Stage A

**Preparation only.** No command in this document has been approved or executed on the physical host. The read-only network diagnostic cannot stop workloads. The version 5 plan/journal is implemented and offline-tested, but the connected-host evidence remains No-Go. A complete offline, quiescent snapshot and separate operator approval are still required. Keep the record below private and available offline.

## Record the original state while connected

Use the same Windows account at the physical console. Save the output in a private directory with access limited to that account, SYSTEM and Administrators. Record the source SHA, time, original child-feature value, RDP policy, `TermService`, listeners, firewall/profile fingerprint, network diagnostic, and all active adapters and routes. Record the physical cable/radio/tether state separately. Do not place raw output in Git or a CI artifact.

Before any workload pause, run `pwsh -NoProfile -File .\scripts\workload-inventory.ps1` from the exact checkout in a same-account physical console with working Docker and WSL read access. It writes one ACL-restricted JSON file under `%LOCALAPPDATA%\ChildStream-Workload-Preflight` and prints only its path, counts and completeness. The file records the exact running container IDs/names, Compose project/service/config paths, mounts, published ports, restart policy, stop settings and health state, plus every WSL distribution and whether it was running. It deliberately excludes container environment variables and secrets. It rereads Docker IDs and WSL state at the end; `Complete=False` means the workload set changed during capture and the record cannot be used for approval. Do not upload the file to GitHub or CI.

The file does **not** identify the human owner of a Compose project, prove whether a bind mount or writable layer contains durable data, establish whether a database flushed its writes, or certify a safe stop/resume sequence. The operator must review the exact private file with each owner. For every running container and distribution, record the owner, application-specific data flush/backup status, pending writes, whether the recorded health state is acceptable, its original restart policy, and the exact owner-approved stop and resumption commands. Preserve the distinction between an originally running and an originally stopped workload. A missing owner, unknown data durability or unhealthy state is a No-Go for pausing that workload. Also record Docker Desktop sign-in behavior and any scheduled restart path. The current host has active Ubuntu and `docker-desktop`; their state must be rechecked immediately before an approved pause.

## Pause only after exact approval

1. Save editor, shell, database and container work. Have each workload owner confirm the private inventory, application-specific flush/backup and exact resumption steps before approving a stop. Docker's graceful signal alone does not guarantee persistent data safety. If a stateful service cannot be stopped with verified recovery, stop the Stage A attempt.
2. Stop each reviewed Compose project with `docker compose stop` from its recorded project directory, or use `docker stop <EXACT_CONTAINER_ID>` for a reviewed standalone container. Do not use `docker compose down --volumes`, `docker rm`, `wsl --unregister`, or delete any switch, endpoint, image or volume. Verify that `docker ps` is empty and record any failed stop.
3. Quit Docker Desktop through its UI. A failed `docker ps` after quitting is expected but **never** proof that containers are gone. The diagnostic accepts `VerifiedStopped` only for a recognized daemon-unavailable error corroborated by accessible process, WSL, HNS endpoint, portproxy, bridge/IP-forwarding and Docker-owned TCP/UDP listener evidence showing no remaining guest or host forwarding path. Permission denial, missing sources, a residual listener or endpoint, or a running WSL distribution leaves the gate Unknown/Fail. If Desktop does not quit cleanly, retain No-Go; do not kill processes blindly.
4. After saving Ubuntu work, use `wsl --terminate Ubuntu`. Recheck `wsl --list --verbose`. If `docker-desktop` remains Running after Docker Desktop has quit, review its owner/state before a separately approved `wsl --terminate docker-desktop`. Do not run `wsl --shutdown` unless all distributions and their work are included in the approval.
5. Ensure the recorded Docker Desktop sign-in option and any workload restart path will not relaunch a guest at the fresh parent logon. If preventing auto-start would require changing a setting, capture its exact old value and obtain separate approval for that reversible change. A pause that cannot survive fresh logon is No-Go. Verify no other VM or guest endpoint is active.

The operator then performs the separately authorized physical disconnection, with a second local observer checking Ethernet, Wi-Fi, Bluetooth PAN, cellular/USB tether, VPN underlays and any other uplink. The read-only diagnostic must show complete sources and independent `External`, `GuestPath` and `RdpExposure` acceptance. An addressed Tailscale or other virtual path remains Unknown without independent attribution; do not whitelist it by name or silently change its state. A connected-network firewall failure remains a connected-network blocker; do not edit its rules. The v5 `plan-boundary` command binds the complete private snapshot to an exact approval hash and journal, then rechecks it before the feature write, after the API call, after the fresh console logon, throughout recovery and before reconnect assessment. See [external-boundary-stage-a.md](external-boundary-stage-a.md) for the **no-journal abort** path if this read-only rehearsal fails.

## Stop, recovery and resumption

If Docker/WSL restarts, an endpoint reappears, a physical link comes up, any bridge query is unknown, or an RDP listener or `TermService` changes unexpectedly, do not advance Stage A. Keep the machine physically offline and preserve the private journal and all before/after inventories. The approved recovery path must verify child absence, restore the exact original child-feature value and separately assess changed RDP/service/listener state before network reconnection. An ambiguous feature write or incomplete restoration is a stop; do not retry it by guesswork.

After a passing reconnect assessment **or the separately verified no-journal abort**, restore cables/radios and any approved sign-in setting to their recorded original values. Relaunch only the previously running WSL distributions and Docker Desktop through their normal owning workflows. Restart the exact reviewed containers/Compose projects, verify volumes and service health, and compare network, WSL, Docker, HNS, RDP, firewall, Sunshine and VDD observations with the private original-state record. Do not assume an originally stopped container should be started. The fresh offline Windows sign-in needed for mutating Stage A remains a separate gate; it is not proven by this read-only rehearsal.

If the workstation cannot hold guests quiescent across fresh logon without interrupting important state, use a separately approved disposable Windows VM with its guest NIC disconnected from all switches instead of the physical host.
