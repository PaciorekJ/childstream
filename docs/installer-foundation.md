# Transactional installer foundation

This branch adds a pure, offline-tested transaction engine. There is **no Windows mutation adapter** and `scripts/setup.ps1 -Mode Apply`, `Recover`, and `Uninstall` still refuse to run. The implementation is suitable for review and fault injection, not a live installation.

## Inventory and ownership

`InstallerInventory.cs` defines separate observations for registry values (presence, exact value type and bytes), child-session feature state, firewall identity and filters, startup resources, owned files, processes, Sunshine installations, and ports. Every observation carries `Absent`, `Accessible`, `Inaccessible`, `Unknown`, or `Conflicting`; failed reads must never be converted to absence. Review output uses a length and SHA-256 for registry data and omits raw value bytes, startup arguments, Sunshine configuration, pairing material, and file contents. Credential-key inventory is refused. The future Windows probe must collect this data with read-only APIs and map access failures precisely. `scripts/diagnose.ps1` remains a separate, narrower read-only diagnostic.

The mutation policy currently permits only files under a dedicated ChildStream-owned root and HKCU values under `Software\ChildStream`. It rejects native Sunshine/VDD paths, global RDP, child-session settings, firewall rules, startup entries, processes, ports, and all other resource kinds before asking a mutation planner to read them. Existing states may be changed only when the adapter proves the transaction's owner marker. An existing desired state is recorded as a no-op; uninstall does not claim or remove it. Lexical normalization rejects relative paths, alternate data streams, and path traversal; existing reparse points on every ancestor are refused. The future Windows adapter must also bind final paths and volume/file IDs from opened handles, detect hard links and 8.3 aliases, check directory ACLs, and revalidate file identities during compare-and-exchange. These checks cannot be made atomic by lexical validation alone. A string owner marker is insufficient on the real host.

## Plan and journal

`InstallerEngine.Plan` reads each allowed target, rejects incomplete/uncertain/conflicting observations, sorts targets, and binds exact original bytes and type, desired state, privilege, ownership evidence, verification, and reversal description into a SHA-256 plan hash. A cross-process exclusive lock file is acquired before planning, Apply, recovery, or uninstall inspect transaction state. A killed owner releases its OS handle; the journal, not the stale lock marker, determines recovery. `Apply` requires the reviewed hash, recomputes it after lock acquisition, checks privilege and current state, and refuses an unfinished earlier journal. This is an application-level approval contract; a future entry point must display the complete plan and obtain explicit operator approval rather than passing its own hash silently.

The journal contains the full original and desired snapshots. It is written and flushed before any mutation. Each changed entry moves `Planned → Prepared → Applied`; the journal moves to `Complete` after all postconditions pass. `Prepared` is persisted before each compare-and-exchange. If the process ends between a mutation and its `Applied` save, recovery compares actual state with the exact original and desired snapshots. `FileJournalStore` distinguishes verified absence, valid, inaccessible, corrupt, unexpected file/reparse type, interrupted replacement, and unknown/conflicting states; every state except verified absence or valid blocks Apply. A leftover `.new` file blocks Apply until an explicit, lock-protected repair validates the replacement. Repair keeps the valid main journal authoritative and archives the replacement, or promotes a complete replacement when the main file is verified absent. Malformed or conflicting replacements remain untouched. The journal is bounded, versioned, SHA-256 checked, and published by atomic same-directory replacement with `Flush(true)`. It is capped at 32 MiB and each inlined resource snapshot at 8 MiB; larger owned files need a separately verified backup store before updates are allowed. The checksum detects corruption, not hostile same-user editing. The eventual installation path must have restrictive ACLs and preserve the journal through uninstall. Power-loss guarantees of file replacement and Windows ACL behavior need live validation.

`RecoverOrUninstall` durably enters `Reversing`, then visits entries in reverse order. An entry already matching its original becomes `Reversed` without a write. An entry matching the transaction's desired state is restored through compare-and-exchange, followed by exact read-back verification. Any other state becomes `Conflict`; the journal and altered resource remain for explicit inspection and retry. Failed reversal leaves `Reversing` or `Conflict` evidence; another process can retry. Success ends at `RolledBack`, which is distinguishable from incomplete recovery. No journal means uninstall cannot claim ownership.

The installer does not automatically enable general RDP. It also does not change the child-session feature or firewall. A controlled, separately authorized experiment must establish whether general RDP enablement is required on the target build before those operations are designed. Network exposure requires a separate rule plan specifying exact identity, executable, protocol, ports, profiles, local and remote address scope, and original-state reversal. No broad rule is admitted by this policy.

## Portable Sunshine contract

`PortableSunshinePackage` requires an exact versioned URL under the [official `LizardByte/Sunshine` GitHub release path](https://github.com/LizardByte/Sunshine/releases), an independently pinned SHA-256, an executable signer thumbprint, and separate, nonoverlapping binary and configuration directories under the owned root. The binary directory's leaf is the immutable version; an update must use a new directory rather than overwrite executable bytes. `Admit` holds a read lock while hashing before and after release-asset provenance verification, then returns the locked stream for extraction. The actual release-asset provenance verifier, extracted-executable signature check, independent pin selection, bounded download, archive traversal defense, safe extraction, and package installation adapter remain to be implemented. The archive itself may be unsigned; its pinned digest and official release identity must be verified before extraction, and the extracted executable signer pin must be checked before execution. Existing native Sunshine service, configuration, and VDD remain inventory-only.

## Launcher reconciliation

The launcher now rejects a fresh connection when the parent already has an associated child. It rechecks immediately before ActiveX `Connect` and holds a session-local single-instance mutex while running. Before WTS logoff, it durably records the parent ID and child ID/logon time in a per-user intent latch. A process restart with that unresolved latch blocks connection, even if the child currently appears absent. A confirmed sign-out clears the latch only after an absent-child query. `ChildStream.exe -reconcile-session` is an explicit, nondestructive recovery command: it checks the same parent twice for absence, clears only the latch, and returns exit code 0 on success or 4 on refusal/error. An existing associated child always blocks a new launcher process; this branch does not add a destructive cleanup command or automatically attach to it. WTS query/connect and query/logoff are not atomic, so live timing and identity checks remain acceptance gates.

## Offline verification and next boundary

`tests/offline.ps1` compiles with the in-box .NET Framework compiler and runs 104 launcher assertions plus 181 installer assertions, without Administrator access or host configuration changes. Installer tests inject failures at each Apply and rollback journal save, before and after each compare-and-exchange, and at temporary-journal publication boundaries. They restart from durable disk journals, verify idempotence and partial rollback, reject stale/altered plans and malformed manifests, exercise privilege and external-drift conflicts, coordinate two processes through the OS lock, and exclude native Sunshine/VDD and broad networking. The Windows PR workflow runs the same script for PRs targeting either `master` or `codex/hardened-foundation`.

The next implementation boundary is a **read-only Windows inventory adapter and a narrow owned-file compare-and-exchange adapter**, with ACL/reparse checks, a secure journal location, and a review/approval CLI. Run all of its mutations against disposable fake or temporary owned test resources first. Do not wire `setup.ps1 -Mode Apply` to the host until independent Windows adapter tests, recovery tests, package signer implementation, package pins, networking decision, and the separately authorized child-session/RDP experiment are complete.
