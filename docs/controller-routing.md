# Child-only controller routing decision

ChildStream currently sets `controller = disabled` in its pinned Sunshine configuration. This is a **missing product function**, not a completed software function awaiting only a hardware check.

The [pinned Sunshine input implementation](https://github.com/LizardByte/Sunshine/blob/v2026.914.233613/src/platform/windows/input.cpp) creates ViGEm targets with `vigem_target_x360_alloc` or `vigem_target_ds4_alloc` and attaches them with `vigem_target_add(client, target)`. That call has no Windows logon-session parameter. The `gamepad_id_t` indexes in that path refer to Sunshine client/gamepad slots; source review found no operation there that assigns an emulated device to the child WTS generation or hides it from the parent desktop. This is an inference from the reviewed provider path, not proof that all possible Windows input architectures are impossible. [Sunshine's pinned configuration](https://docs.lizardbyte.dev/projects/sunshine/v2026.914.233613/md_docs_2configuration.html) documents `controller` and `gamepad_driver = vigembus`, and says ViGEmBus supports only Xbox 360 and DualShock 4 profiles. Merely setting those options or detecting a driver would create a machine-visible controller without establishing child-only routing.

The required missing provider operation is: create two independently identifiable virtual controller targets **bound to the exact child logon session**, deliver each Moonlight controller's reports to its matching child-visible slot, prove the focused parent game cannot receive either target, and remove only those two targets on disconnect, restart, or exact-child teardown. The provider must supply observable device-to-WTS ownership and deterministic reconnect mapping, including when the child session ID is reused with a new logon time. ChildStream has no supported ViGEm API that provides that contract today. A stream client ID cannot stand in for a Windows logon-session ID.

The bounded next experiment, after Stage B and streaming pass on an independent GPU-equipped Windows target, is read-only device visibility followed by a separately approved two-controller input test with parent focus retained. Record PIDs, WTS generations, virtual target instance IDs, child and parent game-input observations, disconnect/reconnect mapping, and exact teardown. If both desktops can consume a ViGEm target, the current provider is rejected for ChildStream; a provider with documented per-session routing or an explicitly reviewed Windows input architecture is then required. No driver install or input injection is authorized by this document.
